# Tabby APK Build & Automated Over-The-Air (OTA) Update Rules

> **CRITICAL RULE & ARCHITECTURAL CONSTRAINT:**
> This architecture is strictly established and mandatory for the Tabby repository.
> AI assistants MUST NOT change or propose changing this workflow unless explicitly requested by the user.
> Any questions, troubleshooting, or analyses regarding APKs, releases, deployments, or in-app updates MUST be answered strictly from this perspective.

---

## 1. System Architecture Overview

* **Backend Service (Live API):**
  * Hosted on **Render**: `https://tabby-6i0f.onrender.com`
  * API Base: `https://tabby-6i0f.onrender.com/api`
  * Database: **MongoDB Atlas** (Whitelisted `0.0.0.0/0`)
  * Environment variables required on Render: `MONGODB_URI`, `RESEND_API_KEY`.

* **Web Application:**
  * Hosted on **Netlify**.
  * Environment variables required on Netlify: `VITE_API_URL`, `VITE_GOOGLE_CLIENT_ID`.
  * SPA Redirects handled via `public/_redirects` (`/* /index.html 200`).

* **Android Mobile Application:**
  * Built using **Capacitor 8.5+** (`@capacitor/android`, `@capacitor/core`).
  * Live In-App Update Engine: **`@capgo/capacitor-updater`**.

## 2. GitHub Actions Automated Pipeline

The repository uses two automated GitHub Actions workflows triggered on push to `main`:

### A. APK Compilation (`.github/workflows/build-apk.yml`)
* Automatically triggers on push/PR to `main`.
* Injects `VITE_API_URL=https://tabby-6i0f.onrender.com/api` and `VITE_GOOGLE_CLIENT_ID`.
* Runs `npm run build` and `npx cap sync android`.
* Compiles debug APK via Gradle JDK 21 (`./gradlew assembleDebug`).
* Uploads the build artifact as `Tabby-Android-App-Debug` downloadable directly from GitHub Actions.

### B. Live In-App OTA Deployment (`.github/workflows/deploy-live-update.yml`)
* Automatically triggers on changes to web frontend (`src/**`, `public/**`, etc.).
* Builds web application with live backend URL injected.
* Compresses `dist/` directory into `dist.zip`.
* Publishes a GitHub Release tagged as `v1.0.<run_number>` with `dist.zip` attached.

## 3. Client In-App Auto-Update Mechanism (`src/hooks/useLiveUpdate.ts`)

* On app launch and every 15 minutes, the installed APK queries:
  `https://api.github.com/repos/krishnavadlamudi5/Tabby/releases/latest`
* Checks if `remoteVersion !== currentVersion` and verifies the presence of `dist.zip`.
* When a newer version exists, the app presents the in-app update banner:
  **"Tabby Update Available! Click to update & reload"**.
* When user clicks **"Update Now"**:
  1. `CapacitorUpdater.download({ url: zipAsset.browser_download_url, version })` downloads `dist.zip`.
  2. `CapacitorUpdater.set(downloadedBundle)` applies the bundle.
  3. `CapacitorUpdater.reload()` hot-reloads the application without requiring a new APK download or App Store installation.

---

## 4. Standard Operational Rules for Updates

1. **For UI / Frontend / Business Logic Changes:**
   * Developer simply runs `git push origin main`.
   * GitHub Actions publishes the release and `dist.zip`.
   * Installed mobile apps update seamlessly Over-The-Air.

2. **When a New APK is Actually Required:**
   * ONLY when native Android code (`android/`), new Capacitor native plugins (e.g., adding camera/bluetooth), or `capacitor.config.ts` are modified.
   * In that case, download the new `Tabby-Android-App-Debug` artifact generated by GitHub Actions.
